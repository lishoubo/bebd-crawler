# 建立 BEBD 本地爬虫最小闭环

## 为什么做

需要从 BEBD 数据中心按品牌采集数据。现阶段目标是先验证登录态复用和单品牌采集，
没有多机调度、在线服务或跨系统同步需求，因此直接复用 `rms-rpa-worker` 的浏览器自动化经验，
但不引入数据库、Redis、任务队列等基础设施。

第一批只处理“欧莱雅”，先把页面结构、请求方式、分页和最终数据字段摸清，再扩展品牌清单。

## 目标

1. 提供独立的登录流程：打开可见浏览器，由用户手工完成登录，然后将完整 cookie 保存到本地文件。
2. 提供独立的采集流程：打开可见浏览器，恢复本地 cookie，按品牌清单进入数据中心并采集数据。
3. 第一阶段支持品牌“欧莱雅”，结果写到本地文件，便于人工核对和后续确定数据模型。
4. 登录失效、页面结构变化或采集不完整时，能够明确报错并保留诊断证据。

## 非目标

- 不引入数据库、Redis、消息队列、Web 服务或定时调度。
- 不在第一阶段支持无人值守登录、自动识别验证码或绕过平台风控。
- 不在尚未观察真实页面和接口前锁死最终字段模型。
- 不承诺第一阶段批量采集全部品牌。

## 成功标准

1. 用户可以运行登录命令，在浏览器中完成登录，cookie 被保存到 Git 忽略的本地目录。
2. 关闭浏览器后再次运行采集命令，无需重复登录即可到达目标数据页；失效时提示重新登录。
3. 以“欧莱雅”为输入，能够遍历目标结果的全部分页，并输出结构化本地文件。
4. 输出至少包含品牌、采集时间、来源页/请求标识和页面中可获得的业务字段；具体字段在页面探查后回填。
5. 采集数量可与页面展示数量交叉核对，并留下日志或截图作为验证证据。

## 约束与原则

- 仅采集用户账号正常可见的数据，遵守站点条款、账号权限和合理请求频率。
- cookie 属于敏感凭证：不得写入日志、测试夹具或 Git；文件权限尽量限制为当前用户可读写。
- 初期浏览器保持可见，便于登录、风控处理和页面行为确认。
